**Scoring convention.** Every `<item>_r<k>` cell takes exactly one of `OK`, `ERROR` or `NOT_ASSESSABLE` (aliases: PASS/FAIL, Y/N, 1/0; and `N/A`, `UNASSESSABLE`, `NOT ASSESSABLE`, `CANNOT_ASSESS`, `UNDECIDABLE` for the third). Leave a cell blank if not yet reviewed; a bare `NA` still parses as "not reviewed yet". `NOT_ASSESSABLE` exists because of the 82 crop-only test rows above: without it a finished review would be indistinguishable from an abandoned one, or the reviewer would have to guess. It is excluded from the agreement, kappa and critical-error denominators and reported separately as `n_not_assessable`. Reviewers must not see each other's columns while scoring. Resolve disagreements by consensus or a third reviewer and record the result in `<item>_adjudicated`.

**How to score.** Each reviewer runs their own instance of the local scoring app and their own output file:

```
python3 -m src.qa_review_app --mode image --reviewer <shortname>
python3 -m src.qa_review_app --mode image --merge --reviewers <r1>,<r2>
python3 -m src.crop_qa --score derived-data/cohort/image_audit_workbook.csv
```

The `--score` step reports raw agreement and Cohen's kappa per item and writes `outputs/tables/image_audit_summary.csv`. **If any item's critical-error rate exceeds 2% the review MUST be expanded**; the command exits 2 in that case and 0 when the gate holds. A critical error is one that **either** reviewer flagged, which is deliberately conservative. `cohens_kappa` prints `undefined (no variation)` rather than 0.0 when both reviewers used a single category, because 0.0 there would read as chance-level agreement on what is most likely a clean audit.
